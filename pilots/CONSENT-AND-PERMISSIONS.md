# Consent and permissions — blank human-executed procedure

Before starting, the responsible human records the participant's voluntary consent,
permitted use of deidentified feedback, retention date, withdrawal contact/process,
and whether quoting is allowed. Declining or withdrawing has no penalty. This file
is a template, not anyone's consent or legal authorization.

Participant confirms they have rights to each dataset and can authorize this local
use. Use synthetic cases if uncertain. Exclude real secrets, credentials, customer
identifiers, employer telemetry and PII. An automated hash or redaction rule does
not establish privacy or rights. No uploading raw data or creating cloud accounts.

Explain the exact workflow: local Python, deterministic mock/imported results,
local report directory, no model provider calls. If external prediction generation
is later proposed, obtain separate explicit consent for destination, fields, model,
retention and cost before transmitting anything. Do not reuse demo consent.

Store actual signatures/contact details separately in an access-controlled system;
PilotRecord references hashes of the consent/permission records. A named custodian
must verify those records before any research/customer-validation claim. Retain
only permitted summaries; on withdrawal remove relevant sources and recompute
aggregates, including obsolete exports and backups under the agreed retention plan.
